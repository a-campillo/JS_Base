00 · Introducción

¿Qué es JavaScript?

  • Creado en 1995 por Brendan Eich en Netscape, en unos 10 días.
  • Estandarizado como ECMAScript. ES2015 (“ES6”) modernizó el lenguaje; desde entonces sale una versión nueva cada año.
  • Se ejecuta en todas partes: navegadores, servidores (Node.js, Deno, Bun), móviles, escritorio (Electron), IoT.
  • Tipado dinámico: las variables no tienen tipo, los valores sí.
  • Un solo hilo con un event loop para el trabajo asíncrono.
  • Multiparadigma: imperativo, orientado a objetos (prototipos), funcional.
Dato curioso: JavaScript no tiene nada que ver con Java. El nombre fue una decisión de marketing de 1995. ☕

Una breve línea de tiempo

  • 1995 Mocha → LiveScript → JavaScript
  • 1997 Estándar ECMAScript 1
  • 2005 Era AJAX: Gmail, Google Maps
  • 2009 ES5 · Node.js lleva JS a los servidores
  • 2015 ES2015: let, const, flechas, clases, módulos, Promesas
  • 2017 async / await
  • 2020 ??, ?., BigInt
  • Hoy Versiones anuales (ES2016 … ES2025+)
  • Recalca: ECMAScript = la especificación; JavaScript = la implementación que usamos.
  • El “tipado dinámico” volverá en Tipos de datos y Operadores: ahí están la mayoría de las sorpresas.

01 · Sintaxis

Los bloques de construcción

  • Las sentencias realizan acciones y terminan en ; (opcional gracias a ASI, pero recomendado).
  • Las expresiones producen un valor: 2 + 2, "a" + "b", isValid.
  • Los bloques agrupan sentencias con { }.
  • Comentarios: // de línea y /* de bloque */.
  • Distingue mayúsculas: myName ≠ myname.
  • Identificadores: letras, dígitos, $ y _; no pueden empezar por un dígito. Usa camelCase.
  • ASI = Automatic Semicolon Insertion (inserción automática de punto y coma). Mejor que el equipo use un linter/formateador (ESLint + Prettier) en lugar de debatir sobre el punto y coma.
  • Prueba: renombra myName en un solo lugar y ejecuta para ver un ReferenceError.
01 · Variables

var, let y const

AlcanceReasignarRedeclarar

letbloque✔✘

Regla práctica: usa const por defecto, let cuando necesites reasignar y evita var.
¿Por qué evitar var? Permite redeclarar la misma variable sin ningún aviso: si dos partes del código usan el mismo nombre, la segunda pisa en silencio a la primera. Con let y const, el error se detecta al instante (SyntaxError).
const hace constante la referencia, no el valor. Los objetos y arrays todavía se pueden modificar.

Pruébalo: descomenta la línea pi = 3 o la redeclaración con let y ejecuta de nuevo.

Las variables no tienen tipo; los valores sí. let v = 1; v = "ahora un string"; es perfectamente válido.
  • typeof null === "object" es un bug que nunca se podrá corregir sin romper la web.
  • Las funciones también son objetos; typeof simplemente las reporta de forma especial.
02 · Tipos de datos

Números (y sus rarezas)

  • Un solo tipo number para enteros y decimales (punto flotante de 64 bits).
  • 0.1 + 0.2 !== 0.3: no es un bug de JS, así funciona el punto flotante binario.
  • NaN (“Not a Number”) es un número… y no es igual a sí mismo. Usa Number.isNaN().
  • Dividir entre cero da Infinity, no un error.
  • Los enteros mayores que 253 − 1 pierden precisión → usa BigInt.
  • Para dinero, trabaja en centavos (enteros) o usa una librería de decimales.
  • parseInt lee hasta donde puede; Number exige que todo el string sea numérico.
02 · Tipos de datos

Strings y template literals

  • Tres tipos de comillas: 'simples', "dobles", `invertidas`.
  • Los template literals permiten interpolar ${expr} y texto de varias líneas.
  • Los strings son inmutables: sus métodos devuelven strings nuevos.
  • Métodos útiles: length, toUpperCase, includes, slice, split, trim, replace, padStart, at.
  • Los template literals aceptan cualquier expresión dentro de ${}, incluidas llamadas a funciones y ternarios.
02 · Tipos de datos

Valor vs. referencia

  • Los primitivos se copian por valor: cada variable tiene su propia copia.
  • Los objetos (incluidos arrays y funciones) se copian por referencia: las variables apuntan al mismo objeto.
  • === entre objetos compara identidad, no contenido.
  • Usa spread { ...obj } / [...arr] para copias superficiales y structuredClone() para copias profundas.
La mayoría de los bugs del tipo “¡mis datos cambiaron solos!” vienen de referencias compartidas.
  • Analogía: un primitivo es una fotocopia de un documento; una variable con un objeto es un enlace compartido a un Google Doc.

03 · Operadores

Comparación: == vs ===

  • === igualdad estricta: mismo tipo y mismo valor. Sin conversiones.
  • == igualdad débil: primero convierte los tipos, con reglas sorprendentes.
  • !== / != son sus versiones negadas.
  • < > <= >= comparan números, o strings alfabéticamente (¡"10" < "9" es true!).
  • Object.is(a, b) es como ===, pero considera NaN igual a sí mismo.
Usa siempre === y !==. La única excepción común: x == null comprueba a la vez null y undefined.

03 · Operadores

¿Truthy o falsy?

En un contexto booleano (if, &&, ||, !) todo valor se convierte en true o false. Hay exactamente 8 valores falsy:

false0-00n""nullundefinedNaN

Todo lo demás es truthy, incluidos "0", "false", " ", [] y {}.

Cuidado con if (items.length) vs if (items): ¡un array vacío es truthy!

  • Deja que el público elija valores: "0", " ", [], {}, NaN… El array vacío y "0" suelen sorprender.
03 · Operadores

Operadores modernos: ?: ?? ?. ...

  • Ternario cond ? a : b: la versión en expresión de if/else.
  • Fusión de nulos a ?? b: usa el valor alternativo solo con null/undefined (conserva 0, "", false).
  • Encadenamiento opcional a?.b, a?.[k], fn?.(): se detiene y devuelve undefined en lugar de fallar.
  • Asignación lógica ??=, ||=, &&=.
  • Spread ...arr expande un iterable u objeto en su lugar.
  • Quita el ?. de user.settings?.theme → TypeError: Cannot read properties of undefined.
  • ?? es el operador correcto para valores por defecto de números, booleanos y strings que pueden ser legítimamente 0/false/"".

04 · Control de flujo

Condicionales: if y switch

  • if / else if / else evalúa las condiciones de arriba abajo; gana la primera truthy.
  • switch compara con === contra cada case.
  • Sin break, la ejecución continúa al siguiente caso (fall-through): útil para agrupar, peligroso por accidente.
  • Para elegir un valor simple, un ternario o un objeto de búsqueda suelen ser más limpios.

Pruébalo: cambia hour y day, o quita un break.

  • Quita el primer break para mostrar el fall-through imprimiendo dos líneas.

Funciones

05 · Funciones

Tres formas de definir una función

Declaración

  • Elevada: se puede llamar antes de su línea
  • Tiene su propio this

Expresión

  • No elevada (TDZ)
  • Un valor asignado a una variable

Flecha ES2015

  • Concisa, retorno implícito
  • Sin this / arguments propios
  • Las tres producen el mismo tipo de valor: un objeto función.
  • Error típico: () => { name } es un bloque, no un objeto. Envuelve los objetos literales en paréntesis.
05 · Funciones

Parámetros y valores de retorno

  • Parámetros por defecto: function f(x = 1)
  • Parámetros rest: function f(...args) agrupa los argumentos extra en un array.
  • Parámetros desestructurados: function f({ name, age }), ideales para objetos de “opciones”.
  • Los argumentos que faltan son undefined; los que sobran se ignoran, sin error.
  • Una función sin return devuelve undefined.
  • Los objetos de opciones hacen legibles las llamadas y vuelven irrelevante el orden de los argumentos.
05 · Funciones

Alcance y closures

El alcance es léxico: una función ve las variables del lugar donde fue escrita, buscando hacia afuera.

Alcance globalconst app = "demo"
function createCounter()let count = 0
() => ++count ve count y app
Un closure (clausura) es una función que recuerda las variables del alcance donde fue creada, incluso después de que la función externa haya terminado.
🪤EjercicioQuiz: la trampa clásica de los closures→
  • Cada llamada a createCounter crea un count nuevo e independiente.
  • Los closures hacen posible: privacidad de datos, fábricas, manejadores de eventos, hooks de React, memoización.
05 · Funciones

Las funciones son valores

Las funciones son ciudadanas de primera clase: puedes guardarlas en variables, pasarlas como argumentos y devolverlas desde otras funciones.

  • Función de orden superior: recibe y/o devuelve una función (map, filter, setTimeout, addEventListener…).
  • Callback: una función que se pasa para ser llamada después.
  • Composición: construir comportamientos complejos a partir de funciones pequeñas.
  • Esta es la base de los métodos de array (siguiente bloque) y de los callbacks asíncronos.
05 · Funciones

this y funciones flecha

  • En una función normal, this depende de cómo se llama: obj.method() → this === obj.
  • Si separas el método (const f = obj.method), this se pierde.
  • Las funciones flecha no tienen this propio: usan el del código que las rodea. Perfectas para callbacks dentro de métodos.
  • fn.bind(obj) crea una copia con this fijo.
No uses funciones flecha como métodos de un objeto cuando necesites this.

  • Mantenlo ligero: this merece su propia sesión. La idea clave: funciones normales para métodos, flechas para callbacks.

06 · Objetos

Objetos

  • Colecciones de pares clave → valor, creadas con { }.
  • Notación de punto obj.key o de corchetes obj["some-key"] / obj[variable].
  • Los métodos son simplemente propiedades que contienen funciones.
  • La desestructuración extrae propiedades a variables, con renombrado y valores por defecto.
  • Spread { ...a, ...b } copia / combina (las claves posteriores ganan).
  • Object.keys, Object.values, Object.entries.
  • El orden del spread importa: las propiedades escritas después del spread sobrescriben las copiadas.
06 · Arrays

Los arrays y sus superpoderes

[🥔, 🌽, 🐔].map(cook) → [🍟, 🍿, 🍗]
[🍟, 🍿, 🍗].filter(isVeggie) → [🍟, 🍿]
[🍟, 🍿].reduce(eat) → 😋
  • map transforma cada elemento → array nuevo, misma longitud.
  • filter conserva los elementos que pasan una prueba.
  • reduce reduce el array a un único valor.
  • find, some, every, includes, indexOf.
  • push, pop, sort, splice modifican el array original.
