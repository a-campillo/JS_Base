Errores y asincronía

Un bloque extra para cuando sobra tiempo o para repasar después de la sesión: cómo manejar errores y cómo JavaScript trabaja con tareas que tardan.

try / catchthrowerrores propiosevent loopPromiseasync / await

Manejo de errores

  • throw lanza cualquier valor, pero es mejor usar objetos Error (incluyen el stack trace).
  • try ejecuta el código, catch maneja el error, finally se ejecuta siempre (limpieza).
  • Tipos incorporados: Error, TypeError, RangeError, ReferenceError, SyntaxError.
  • Extiende Error para errores propios de tu dominio.
  • Un error no capturado detiene el script actual.
💡 Notas para el presentador
  • Cambia divide(1, 0) por divide("1", 2) para activar la rama del TypeError.

El event loop

JavaScript hace una cosa a la vez. El trabajo lento (temporizadores, red, archivos) se delega y su callback queda en cola para después:

  1. Primero se ejecuta todo el código síncrono.
  2. Luego las microtareas: callbacks de Promesas (then, await).
  3. Luego las macrotareas: setTimeout, eventos, E/S.
setTimeout(fn, 0) no significa “ahora”, sino “lo antes posible después del trabajo actual”.

Promesas y async / await

  • Una Promesa representa un valor que estará disponible más tarde: pending → fulfilled o rejected.
  • Se consume con .then() / .catch()…
  • …o con await dentro de una función async: se lee como código síncrono y usa try / catch normal.
  • Promise.all([...]) ejecuta varias en paralelo.
Ejemplo real: const res = await fetch(url); const data = await res.json();
💡 Notas para el presentador
  • Fíjate en los tiempos: “¡Yo me ejecuto primero!” aparece de inmediato; lo demás tras ~0,8 s y ~1,6 s.
